# lanelessKaralakou notebook reference

This document describes the retained safeRL system as implemented by
notebooks/lanelessKaralakou.ipynb. The notebook is the source of truth for
the environment and reward definitions. The Python files in scripts/ are
operational entry points that load selected notebook cells and add
resumability, parallelism, validation, or reporting.

## Research scope

The experiment is a continuous-control lane-free highway problem:

- the ego and surrounding vehicles move on a periodic road with no lane
  indices, lane-change commands, or target lanes;
- surrounding traffic is generated by the MTM model with a continuous
  cautious-to-aggressive personality;
- the policy controls physical longitudinal and lateral acceleration;
- a hard high-order control-barrier-function (HOCBF) filter can modify the
  physical command before it reaches the simulator;
- safety learning is compared through reward feedback, detached actor
  guidance, differentiable mean projection, and external deployment
  shielding.

The study deliberately separates what the policy learns from what the runtime
filter supplies. A CBF-OFF result measures the policy action map. A CBF-ON
result measures that policy plus the deployed shield.

## Canonical experiment contract

| Item | Canonical value | Meaning |
| --- | ---: | --- |
| Environment ID | lane-free-v0 | Registered by lane_free_env.py |
| Traffic model | MTM | Congested and uncertain surrounding traffic |
| Road | 380 m by 10.2 m ring | Longitudinal distance wraps around |
| Vehicles | 55 total | One controlled ego plus surrounding traffic |
| Neighbor rows | 5 | Nearest sensed vehicles are exposed to the policy |
| Physics | dt = 0.01 s, 100 Hz | Ten simulator frames per policy action |
| Policy rate | 10 Hz | One action is held for ten physics frames |
| Acceleration bounds | ax, ay in [-3, 3] | The common physical action box |
| Ego speed target | 16 m/s | Fixed target used by reward and observation |
| Surrounding desired speeds | 15 to 25 m/s | Sampled traffic speed range |

| Evaluation task | 1,000 m | Collision-free distance completion |
| Evaluation timeout | 3,000 policy steps | Guard against non-progressing rollouts |

The lower-level lane-free environment has a larger default configuration for
general demos. The notebook cell named A.1 replaces those defaults with the
canonical study contract above.

## Observation and action interfaces

### Canonical PPO observation

The base environment emits one row for the ego and five rows for neighbors.
With vehicle dimensions excluded, each row is:

    [dx, dy, vx, vy, v_desired]

The reward wrapper reuses the ego row's first two slots as normalized ego y
and normalized target y, exposes the dynamic target speed in the ego speed
slot, and preserves the remaining 25 neighbor features. The resulting
vehicle table is 30D. The previous normalized executed action

    [a_x, a_y]

is appended to form the 32D PPO state.

The previous action is the command that was actually executed after the
relevant projection/filtering stage, not an unfiltered latent policy sample.
This keeps the state semantics consistent with the transition experienced by
the simulator.

### Legacy DDPG observation

The retained DDPG reference uses the older flat 42D table with seven features
per row, including vehicle dimensions. The notebook's C.1 preflight asserts
the shape before training. This legacy interface is intentionally documented
separately from the canonical 32D PPO interface.

### Action path

The policy outputs a normalized two-dimensional action. The environment
adapter maps it to physical acceleration using the configured bounds. For a
CBF-enabled run, the path is:

    policy latent output
        -> optional differentiable mean projection
        -> sampled-action hard projection
        -> ten physics-substep HOCBF checks
        -> LaneFreeTrafficEnv integration

The raw policy command, safe command, applied command, correction, solver
status, and fallback status are logged independently.

## Karalakou reward

The reward wrapper in notebook cell A.0 computes:

    r = epsilon_r / (epsilon_r + wx*cx + wy*cy + wf*cf + way*cay)
        + progress_reward - jerk_penalty
        + collision_or_overtake_adjustment

The principal terms are:

- cx: normalized ego-speed error from the current target speed;
- cy: normalized lateral error from the selected target y;
- cf: potential-field cost from nearby vehicles;
- cay: lateral-acceleration comfort cost;
- progress_reward: forward metres normalized by the fixed
  progress_distance_scale_m, currently 2.0 m;
- jerk_penalty: bounded cost based on the change in applied acceleration;
- collision penalty: -2.5 in the canonical reward;
- overtake bonus: +0.5 for a detected overtake.

The target-speed transition parameters remain in the configuration for
backward-compatible artifacts, but the canonical ego target is the fixed
16 m/s value. Progress is distance-normalized; it is not normalized by
elapsed time or target speed.

The wrapper publishes reward components under the karalakou_ prefix in info.
Important fields include karalakou_cf, karalakou_target_y,
karalakou_target_speed, karalakou_lat_y_error_m, karalakou_ego_speed,
karalakou_abs_speed_deviation, progress_m, jerk_norm, and ego_collision.

## PPO/CBF research ladder

The canonical B section defines seven policies. Each policy is trained for
1,000,000 environment transitions with seed 307, 20 rollout environments,
global rollout size 1,000, batch size 100, ten PPO epochs, and checkpoints
every 100,000 transitions.

| Variant | Execution during training | Safety learning signal |
| --- | --- | --- |
| ppo_nominal | No CBF | Ordinary PPO only |
| ppo_cbf_reward | Non-differentiable hard CBF | Correction and intervention reward |
| ppo_cbf_nd_reward_actor | Non-differentiable hard CBF | Reward plus detached safe-mean actor target |
| ppo_cbf_nd_actor_only | Non-differentiable hard CBF | Detached safe-mean actor target only |
| ppo_cbf_diff_reward_only | Differentiable mean projection plus hard sampled/substep projection | CBF reward; explicit mean loss is zero |
| ppo_cbf_integrated_actor_only | Differentiable projection plus hard sampled/substep projection | CBF reward plus mean-internalization loss |
| ppo_cbf_projected_reward_off | Differentiable projection plus hard sampled/substep projection | Mean-internalization loss; CBF reward is off |

The names in the notebook's prose use “reward + actor” for the sixth row and
“actor only” for the seventh row. The implementation variant names and
coefficients in cell B.0 are authoritative.

For every policy, the notebook launches an immediate paired evaluation:

- 200 complete episodes with external CBF OFF;
- the same 200 scenario seeds with external CBF ON;
- a 1,000 m distance cap;
- collision terminates the episode and prevents completion;
- every required KPI must be present before the cell returns.

The seven variant jobs are sequential so that each owns its 20-worker rollout
pool. The learner remains one PPO model per variant; workers only collect
rollouts.

### Launch guard

The prose at the top of the notebook says the launch switch is conservative,
but the current B.0 code sets PPO_1M_RUN_TRAINING to True. Set it to False
before a documentation-only or inspection pass. The same cell also requires

does not infer a safe dry-run default from the prose alone.

## CBF geometry and filtering

The CBF rows use an inflated ellipse around each rectangular vehicle:

    a = length / sqrt(2) + 2*eps_side
    b = width  / sqrt(2) + 2*eps_side

For a relative centerline displacement, the ellipse boundary radius is
computed along the displacement ray. The pairwise barrier is:

    h = ellipse_radius - required_centerline_distance

The HOCBF condition uses:

    psi1 = h_dot + k1*h
    psi2 = h_ddot + k1*h_dot + k0*h >= 0

The canonical notebook values are eps_side = 0.10, k0 = 5.29, k1 = 3.68,
neighbor range = 90 m, maximum neighbor constraints = 12, and feasibility
tolerance = 1e-3.

The filter adds pairwise neighbor rows and lateral boundary rows to a
two-dimensional linear constraint system. It first tests whether the raw
action is feasible. If not, it projects the action onto the bounded
polytope using the exact active-set 2D path. OSQP is retained as a numerical
fallback for degenerate cases. If no feasible result is available, the
least-violating bounded action and then an evasive emergency action are used.

The reset guard checks h and psi1 before the first action. The runtime guard
records the minimum h, h_dot, HOCBF margin, maximum constraint violation,
projection solver, QP status, and fallback status. CBF-enabled notebook runs
recompute the shield at all ten simulator substeps.

## Evaluation and KPI protocol

The standard ten KPI fields are defined in
scripts/evaluate_laneless_karalakou.py:

| Display name | CSV field |
| --- | --- |
| Episode return | episode_return |
| Episode length (steps) | episode_length_steps |
| Ego collisions / km | ego_collisions_per_km |
| Minimum h | h_min |
| QP failure rate | qp_failure_rate |
| Abs speed error (m/s) | mean_abs_speed_deviation |
| Mean lateral tracking error (m) | mean_lat_y_error_m |
| Intervention rate | event_intervention_rate |
| Correction norm | mean_correction_norm |
| Mean jerk norm | mean_jerk_norm |

The PPO post-training table adds Distance-based completion rate. A completed
episode must reach the capped task distance without a collision. Distance
alone is not enough: a rollout that reaches 1,000 m after a collision is not a
successful completion.

The evaluators write per-episode progress after every completed episode.
Depending on the runner, the companion files are named progress.json,
evaluation_progress/, or an output-suffixed episodes-progress CSV. These
files make interrupted long evaluations inspectable without treating a
partial table as complete.

## Legacy DDPG reference

The C section is retained because it provides the historical baseline against
which the newer PPO ladder is interpreted:

1. plain DDPG uses the flat 42D legacy observation;
2. DDPG-CBF uses the tuned no-slack shield and correction reward;
3. guided DDPG-CBF adds a replay-buffer intervention record and an auxiliary
   actor imitation loss;
4. the appendix preserves the historical safety-potential reward comparator.

These runs use the same lane-free environment and CBF geometry but are not
part of the canonical seven-policy PPO total. The scripts
train_ddpg_ego_y_only_50k.py, train_ddpg_y_target_50k.py,
train_ddpg_cbf_500k.py, train_ddpg_cbf_ray_mask.py, and
train_safety_potential_variants.py provide safer out-of-process or repeatable
entry points.

## Artifact layout

The notebook's canonical roots are:

    artifacts/lanelessKaralakou/
    artifacts/1MRun/<variant>/

Typical run artifacts include:

- model or checkpoint files;
- run_config.json and an immutable training signature;
- training and evaluation CSV traces;
- TensorBoard metadata and event files;
- post_train_200ep_kpis.csv for the immediate PPO comparison;
- state-bank, occupancy, and factorial-effect CSV files for counterfactual
  analysis;
- PDF/PNG plots generated by the reporting scripts.

The committed root ppo_* directories contain compact result manifests and
JSON summaries from safeRL runs. Large models, new event logs, videos, plots,
and generated CSVs are ignored by Git. Paths embedded in older manifests may
refer to the workstation that produced the result; use the recorded
configuration and hashes for provenance, not the absolute path.

## Recommended workflows

### Environment smoke test

    Set-Location highway-rl-decision-making
    python scripts\mtm_laneless_smoke.py --run-dir <source-run> --output-dir <output>

The smoke runner compares force and MTM surrounding traffic without launching
an RL learner.

### Nominal PPO pilot

    python scripts\run_nominal_ppo_parameter_pilot.py --help

This screens Q0_current_aligned, Q1_stable, Q2_exploratory, and
Q3_conservative_update while keeping the lane-free task and reward fixed.

### PPO progression

    python scripts\run_ppo_cbf_progression.py --help

Use an explicit output directory. The runner verifies training signatures,
checkpoint completeness, evaluation coverage, and post-training summaries
before reusing an existing run.

### Factorial CBF study

    python scripts\run_cbf_filter_ablation.py --help
    python scripts\evaluate_cbf_counterfactuals.py --help
    python scripts\build_cbf_ablation_report.py --help

This separates policy occupancy effects from same-state action-map effects.
Read diagnostic_scenarios.md before changing the scenario or state-bank
protocol.

### Rendering

    python scripts\render_laneless_karalakou.py --help
    python scripts\render_laneless_policy_scenario.py --help
    python scripts\render_laneless_policy_videos.py --help

Rendering consumes saved models and should be run after selecting the traffic
profile, CBF mode, and artifact suffix explicitly.

## Verification checklist

Before accepting a new result:

1. confirm that the canonical notebook hash and environment/reward config are
   recorded;
2. confirm the action bounds and observation shape;
3. confirm the training seed, traffic model, and rollout topology;
4. distinguish raw, safe, and actually executed actions in the logs;
5. require complete evaluation rows for both CBF modes;
6. interpret raw safety changes as policy internalization and CBF-ON-only
   changes as possible runtime-filter effects;
7. run the unit/protocol tests after changing geometry, wrappers, or
   aggregation.
